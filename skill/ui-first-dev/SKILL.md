# UI 优先开发流程（强制）

## 为什么有这个技能

用户明确反馈过：**"叫你开发一个 APK，你没做 UI 设计就直接开发，结果界面很丑。"**
根因不是写代码慢，而是跳过了设计。所以本技能是硬约束，不是建议。

## 触发条件（命中就执行）

- 要**新建**一个有界面的东西：APK、App、Web 页面、小程序、桌面端、管理后台
- **新增页面 / 新模块**（会多出新界面）
- **改整体视觉风格**、换皮、用户说"丑/难看/太简陋"
- 用户问"开发流程怎么走""先做什么"

不触发：纯脚本、纯后端接口、纯数据处理、只改一行文案。**边界判断：用户"看得见"的东西会不会变？会变就走。**

## 硬规则（违反就是没执行本技能）

1. **P1 未过审，禁止写任何界面代码。** 可以先搭工程骨架、装依赖，但不能有真实界面。
2. 设计必须**先出可点击高保真原型 + 设计 token + 截图**，不是文字描述，不是口头方案。
3. 每阶段结束**停下**，按"门禁汇报卡"汇报，等用户明确说"过/可以/继续"才进下一阶段。
4. 用户没回复 → **不推进**（可写文档骨架，不动下一阶段实体产物）。
5. 用户要求跳过 → 说清后果，照做，并把决定写进项目 `docs/DECISIONS.md`。
6. 设计 token 是前端唯一取色/取字号来源，**禁止硬编码** hex / 字号 / 间距魔法值。

## 各阶段动作

### P0 需求与边界
- 问 5 个问题：谁用/什么场景、必须有的 3–5 个功能、**明确不做什么**、成功标准、技术栈（新项目由你提方案让用户确认，**不要默认替用户决定**）。
- 产物：项目 `docs/PRD.md`（复制模板填）。
- 用户答不上来 → 给建议 + 默认值让他挑，不要问开放题。
- 门禁①：复述目标 + 边界，问"对吗？"

### P1 UI 设计（核心）
1. **取设计系统**：调用 `ui-ux-pro-max` 技能做 `--design-system` 查询（产品类型 + 行业 + 风格关键词）。禁止凭空配色、禁止默认浏览器蓝。
2. **出 2–3 套方向**：每套 = 风格板（色板 hex / 字体与字号阶梯 / 圆角 / 阴影 / 按钮卡片样式）+ 该方向下**一屏主界面**。让用户**选**，不是让他评判。
3. **铺全屏**：以 `templates/prototype/index.html` 为脚手架，改成本项目每一屏。
4. **补状态**：每屏四态（默认/空/加载/错误）；按钮 5 态；输入框 4 态。空态要有引导，错误态要说人话 + 可重试。
5. **落文档**：`docs/UI-DESIGN.md`（为什么这么设计）、`docs/design-tokens.json`、`docs/UI-LOCK.md`（锁版日期与版本）、原型放 `docs/prototype/index.html`、截图放 `docs/prototype/shots/`。
6. **自检**：跑 `CHECKLIST-UI.md` 的 A–F 组，全绿再交。
- 门禁②：给可点原型 + 每屏截图 + 每屏用途；请求："过审请回「过」；要改说屏编号 + 具体问题。"
- 过审后：**元素位置/尺寸/层级/留白以原型为准**；开发中要改样式的，回 P1 说，不许"顺手优化"。

### P2 前端实现（mock 数据）
- 按原型 1:1 还原；技术栈沿用项目，新项目用 P0 确认的。
- token 统一（`tokens.css` / theme），禁硬编码；接口层统一封装 + mock 层，切真接口只改一处。
- 覆盖所有原生默认控件样式；禁 emoji 当图标；禁不可点的假按钮。
- 每屏完成 → 自己截图对原型，偏差先自己修。
- 门禁③：运行方式 + 每屏截图 + **与原型的有意差异清单**。

### P3 接口契约 + 后端
- 先写 `docs/API-CONTRACT.md`（端点/入参/出参/错误码/分页/鉴权/单位时区），再写 mock server，再接真接口。
- 门禁④：契约摘要 + 已连通端点 + 未通项及原因。

### P4 联调与验收
- 按 `docs/ACCEPTANCE.md` 逐条勾；测空数据/超长文本/断网/慢网/重复提交/401。
- 证据：Web 390/768/1280 三宽；APK **真机装机截图**（附机型）。
- 门禁⑤：验收表 + 截图 + 遗留问题（影响 + 建议）。

### P5 交付与收尾
- 安装包/网址 + README（怎么装怎么用怎么改）+ 版本变更记录；交付前 `CHECKLIST-UI.md` 全绿。
- 用户说"收尾" → 触发 `session-handoff` 技能写大脑仓库。

## 门禁汇报卡（照抄这个格式）

```
【<阶段名> · 阶段汇报】
产物：<文件路径 / 可访问链接 / 截图>
结论：<一句话：做完了什么、能不能用>
差异/遗留：<与上一阶段不一致处、已知问题>
下一阶段：<阶段名 + 预计做什么>
请你：回复「过」我继续；要改就说屏编号 + 具体哪里不对
```

不允许只说"做好了"而没有产物；没有产物不算过门。

## 反丑 10 条（设计/前端都照此把关）

1. 一个主色 + 中性色阶梯 + 语义色各 1，不彩虹。
2. 字号阶梯 ≤5 档，正文 16px 起，最小 14px。
3. 间距走 8pt 栅格（4/8/12/16/24/32/48）。
4. 圆角 ≤3 档、阴影 ≤3 档，全站同语言。
5. 图标同一套 SVG，禁 emoji、禁线性填充混用。
6. 原生控件样式必须全部重写。
7. 每屏四态齐全，空/错态也要好看。
8. 触控 ≥44×44，底部导航 ≤5。
9. 对比度 ≥4.5:1，深浅色都过一遍。
10. 动效 150–250ms 且服务理解，不炫技不遮挡。

## 例外（必须留痕）

| 情况 | 做法 |
| --- | --- |
| 只修 bug / 改文案 | 直接改，交付附一屏截图 |
| 单屏小迭代 | 先给该屏截图 → 点头 → 改 → 给改后截图 |
| 用户说"先跑起来，跳过设计" | 说清后果 → 照做 → 记入 `docs/DECISIONS.md`（跳过原因 + 补齐时间） |
| 用户说"就按你的来" | 仍要给方向选择/一次确认，不能默默替他决定审美 |

## 精简内联模板（规范目录不可用时）

- **PRD**：用户画像 / 场景 / 必须有功能 3–5 条 / 明确不做 / 成功标准 / 技术栈 / 设计倾向 3 词
- **UI-DESIGN**：风格关键词、主色 hex + 中性色阶梯 + 语义色、字体与字号阶梯表（级别/字号/字重/行高/用途）、间距圆角阴影档位、组件规格与状态、每屏说明（目标/关键元素/主操作/四态）、动效时长
- **ACCEPTANCE**：功能对照 PRD 逐条 ✅/❌、界面还原对照原型、状态与异常 10 项、设备适配、性能底线、交付物核查、遗留问题
