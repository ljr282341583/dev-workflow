### 2.6 带界面项目的开发流程（UI 优先，强制）

> 起因：2026-11 一次"跳过 UI 设计直接写代码、成品难看"的返工。适用于 APK / App / Web / 小程序 / 桌面端 / 后台 / 新页面 / 整体换风格；纯脚本、纯后端、纯数据处理不适用。

- **先加载技能**：任务命中上述范围时，先调用 `ui-first-dev` 技能再动手。
- **六阶段五门禁**：P0 需求卡 → P1 UI 设计（2～3 套风格方向供用户选 → 全屏可点击高保真原型 + 设计 token + 每屏截图）→ **用户过审** → P2 前端（mock 数据，1:1 还原原型）→ P3 接口契约 + 后端 → P4 联调验收（真机 / 390-768-1280 三宽截图）→ P5 交付。
- **门禁不可跳过**：每阶段结束按「产物 + 结论 + 差异遗留 + 下一阶段 + 请用户确认」汇报；用户明确说"过 / 可以 / 继续"才进入下一阶段；用户未回复则不推进。
- **硬禁令**：UI 未过审不得写界面代码；不得用原生默认控件裸样式交付；颜色 / 字号 / 间距 / 圆角 / 阴影统一取 `design-tokens.json`，禁止硬编码；图标禁止 emoji；每屏须齐 默认 / 空 / 加载 / 错误 四态。
- **证据制**：每阶段须附真实截图，不接受"我做好了"式口头结论。
- **例外留痕**：改 bug / 改文案走快捷通道（附一屏截图）；用户明确要求跳过设计 → 说清后果后执行，并记入该项目 `docs/DECISIONS.md`。
- 规范正文与模板：`projects/开发规范/`（`WORKFLOW.md`、`CHECKLIST-UI.md`、`templates/`）；用户视角使用手册见大脑仓库 `教程4-UI优先开发流程.md`。
