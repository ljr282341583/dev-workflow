## 开发流程红线(有界面的项目一律执行)

- **触发**:要开发/新建带界面的东西(APK、App、Web、小程序、桌面端、管理后台、新页面、整体换风格),先调用 `ui-first-dev` 技能,按其流程走。**不得跳过 P1 UI 设计直接写界面代码。**
- **阶段**:P0 需求卡 → P1 UI 设计(可点击高保真原型 + 设计 token + 每屏截图)→ **用户过审** → P2 前端(mock 数据,1:1 还原原型)→ P3 接口契约 + 后端 → P4 联调验收(真机/三宽截图)→ P5 交付。
- **门禁**:每个阶段结束必须停下来,按"门禁汇报卡"给「产物 + 结论 + 差异/遗留 + 下一阶段 + 请你确认」,用户明确说"过/可以/继续"才进入下一阶段;用户没回复不推进。
- **禁令**:UI 未过审不写任何界面代码;禁止用原生默认控件裸样式交付;颜色/字号/间距/圆角/阴影一律走 `design-tokens.json`,禁止硬编码;图标禁 emoji;每屏必须有 默认/空/加载/错误 四态。
- **证据**:每阶段交付必须有真实截图,不接受"我做好了"式口头结论。
- **例外**:修 bug/改文案走快捷通道(改动附一屏截图);用户要求跳过设计 → 说清后果后照做,并把决定记进项目 `docs/DECISIONS.md`(跳过是用户的权利,留痕是流程的义务)。
- **正文与模板**:`{{SPEC_ROOT}}\`(WORKFLOW.md / CHECKLIST-UI.md / templates/)。规范是唯一权威,README 只做索引。
- **使用手册**:大脑仓库 `教程4-UI优先开发流程.md`(话术、门禁怎么回、不懂设计怎么审 UI)。
- 与"跨机接力约定"的衔接:每个门禁的决策同步记入项目 `docs/DECISIONS.md`;收尾时照常写大脑仓库。
